# WorkMate AI — Code-by-Code & Page-by-Page System Architecture Guide
*Comprehensive Technical Manual: Monorepo Structure, Database Models, Backend API Endpoints, Frontend Web Components, Mobile Architecture, and Complete Incident Lifecycle*

---

## 🌟 Executive Overview: What is WorkMate AI?

In modern cloud-native enterprises (such as Netflix, Uber, or Amazon), critical distributed systems experience failures continuously: database deadlocks, payment gateway timeouts, microservice latency spikes, or Kubernetes pod crashes.

In traditional organizations, when an incident occurs:
1. Support agents file generic, unstructured tickets in Jira.
2. Incidents sit in unassigned triage queues for hours.
3. Once assigned, engineers waste 45+ minutes manually querying logs to deduce the root cause.
4. Contractual Service Level Agreements (SLAs) are breached, resulting in direct revenue and customer trust loss.

**WorkMate AI** solves this problem by delivering an enterprise **IT Service Management (ITSM) and Fleet Command Platform** that unifies three core capabilities:
- **Jira Functionality**: Project tracking, 5-stage Kanban lifecycle, and granular work orders.
- **ServiceNow Functionality**: Monitored microservice catalog, fleet health statuses, and real-time SLA compliance countdown timers.
- **Frontier AI Copilot (Google Gemini)**: Autonomous diagnosis engine that instantly parses error messages, infers root causes, and generates step-by-step remediation procedures with SLA targets.

## 🏗️ Monorepo High-Level Architecture

WorkMate AI is structured as a TypeScript monorepo with clean separation of concerns:

```
                            WORKMATE AI MONOREPO
                                     │
         ┌───────────────────────────┼───────────────────────────┐
         ▼                           ▼                           ▼
    [apps/api]                  [apps/web]                  [apps/mobile]
Backend API Server           Web Management Portal       On-Call Mobile App
(Node/Express + Prisma)      (Next.js 15 + React 19)     (Expo React Native)
Port: 4000                   Port: 3000                  Port: 8081
```

### Communication Flow:
- **Web Portal** communicates with the Backend API over HTTP REST at `http://localhost:4000/api`.
- **Mobile App** dynamically resolves the host computer's Wi-Fi LAN IP (e.g., `http://192.168.137.200:4000`) to connect seamlessly from physical Android and iOS devices.
- **Database Connection**: The Backend API connects to **Neon Serverless PostgreSQL** via direct pooled connections with schema synchronization via Prisma ORM.

## 🗄️ PART 1: The Database Layer (`apps/api/prisma`)

The database layer serves as the single source of truth for the entire platform.

### 📄 `apps/api/prisma/schema.prisma`
This file defines the data contracts and relational models:

#### 1. `model User`
Represents team members, engineers, managers, and administrators.
- `id`: Unique cuid identifier.
- `name`: Full name of the user.
- `email`: Corporate email address (unique).
- `password`: Salted and hashed password using `bcryptjs` (10 rounds).
- `role`: Role enum (`SUPER_ADMIN`, `ADMIN`, `MANAGER`, `ENGINEER`, `USER`).
- `department`: Assigned engineering squad (e.g., *Backend & Core APIs*, *DevOps & Cloud SRE*).
- `avatar`: Profile image URL.
- Relations: `assignedIssues`, `reportedIssues`, `tasks`, `comments`.

#### 2. `model Issue` (The Incident Ticket)
Represents the core ticket tracked throughout the system.
- `ticketNumber`: Auto-incrementing integer (e.g., `#TIK-001`, `#TIK-002`).
- `title` & `description`: Summary and detailed error stacktrace.
- `status`: Lifecycle enum (`OPEN`, `ASSIGNED`, `IN_PROGRESS`, `RESOLVED`, `CLOSED`).
- `priority`: Severity enum (`LOW`, `MEDIUM`, `HIGH`, `URGENT`).
- `category`: Category enum (`SOFTWARE`, `HARDWARE`, `NETWORK`, `FACILITY`, `SAFETY`, `OTHER`).
- **Autonomous AI Fields**:
  - `aiRootCause`: AI-inferred technical failure reason.
  - `aiSuggestedAction`: Step-by-step remediation guide generated by AI.
  - `aiConfidence`: Confidence score between 0.00 and 1.00 (e.g., 0.92 for 92%).
- **SLA & Compliance Fields**:
  - `slaDeadline`: Calculated timestamp deadline based on service SLA targets.
  - `slaBreached`: Boolean indicating if the incident exceeded allowed resolution time.
  - `resolvedAt`: Timestamp when ticket status was changed to `RESOLVED`.
- Relations: `serviceAssetId`, `assigneeId`, `reporterId`, `comments`, `tasks`.

#### 3. `model ServiceAsset` (Monitored Microservice / Project)
Represents applications, APIs, clusters, and databases in the organization catalog.
- `name`: e.g., *Billing & Payment Gateway*, *Customer Web Portal*, *Kubernetes Cluster*.
- `slug`: Unique identifier slug.
- `type`: `WEB_APP`, `MOBILE_APP`, `API_SERVICE`, `CLOUD_INFRA`, `DATABASE`, `HARDWARE`, `FACILITY`.
- `environment`: `PRODUCTION`, `STAGING`, `ON_PREMISE`.
- `healthStatus`: `OPERATIONAL`, `DEGRADED`, `OUTAGE`.
- `slaTargetMins`: Target resolution time in minutes (e.g., 15 mins for payment APIs, 60 mins for internal tools).

#### 4. `model Task` (Work Order Checklist Item)
Granular engineering actions attached to an incident or standalone.
- `title`: e.g., *"Failover to secondary Stripe payment gateway"*.
- `status`: `TODO`, `IN_PROGRESS`, `DONE`.
- `priority`: Numeric priority scale (1 = Highest).
- `ownerId`: Assigned engineer.

#### 5. `model Comment`
Real-time audit log and discussion thread.
- `content`: Text of the remediation note or update.
- `isAiGenerated`: Boolean flag marking autonomous AI copilot notes.
- `authorId`: Author user reference.

## ⚙️ PART 2: The Backend Server (`apps/api/src`)

### 📄 `apps/api/src/server.ts`
- Imports `app.ts` and initializes the HTTP listener on port `4000`.
- Binds to host `0.0.0.0` so requests originating from both `localhost` and remote LAN mobile devices are accepted.

### 📄 `apps/api/src/app.ts`
- **CORS Configuration**: Configures open cross-origin resource sharing for web and mobile clients.
- **Express JSON Middleware**: Parses incoming JSON request payloads.
- **Route Registration**: Mounts modular sub-routers:
  - `/api/users` ➔ `user.routes.ts`
  - `/api/issues` ➔ `issue.routes.ts`
  - `/api/services` ➔ `service.routes.ts`
  - `/api/tasks` ➔ `task.routes.ts`
  - `/api/stats` ➔ `stats.routes.ts`
  - `/api/ai` ➔ `ai.routes.ts`
- **Global Error Handler**: Catches unhandled exceptions and formats clean JSON error responses.

---

### 🛣️ Backend API Routes (`apps/api/src/routes/`)

#### 1. `apps/api/src/routes/user.routes.ts` — User & Authentication Engine
- **`POST /api/users/login`**:
  - Validates `{ email, password }`.
  - Queries Neon PostgreSQL with case-insensitive email match.
  - Verifies password hash using `bcrypt.compareSync()`.
  - Rejects invalid passwords with HTTP 401: *"Invalid password. Please check your credentials."*
  - Strips password hash from user object and returns authenticated session payload.
- **`POST /api/users`**:
  - Validates payload with Zod schema (`name`, `email`, `role`, `department`, `password`).
  - Hashes password (minimum 6 characters, defaults to `WorkMate@123` if omitted).
  - Persists new team member in Neon PostgreSQL.
- **`PATCH /api/users/:id`**:
  - Allows users to update their profile name, email, avatar URL, or password.
- **`DELETE /api/users/:id`**:
  - SuperAdmin authority deletion of user accounts.

#### 2. `apps/api/src/routes/issue.routes.ts` — Incident Ticket Workflow Engine
- **`POST /api/issues`**:
  - Validates ticket parameters with Zod schema.
  - Computes `slaDeadline` using the target service asset's `slaTargetMins`.
  - If `runAiTriage: true`, invokes `ai.service.ts` to diagnose root cause, calculate severity, and propose step-by-step remediation.
  - Persists ticket and broadcasts creation to clients.
- **`GET /api/issues`**:
  - Fetches tickets with relational joins (`reporter`, `assignee`, `serviceAsset`, `comments`, `tasks`).
  - Supports filtering by status, priority, department, and role scope.
- **`PATCH /api/issues/:id`**:
  - Updates ticket lifecycle state (`OPEN` ➔ `IN_PROGRESS` ➔ `RESOLVED` ➔ `CLOSED`).
  - Automatically calculates if the SLA was met or breached based on `resolvedAt` vs `slaDeadline`.
- **`POST /api/issues/:id/comments`**:
  - Posts user or AI-generated remediation comments to the ticket audit thread.

#### 3. `apps/api/src/routes/service.routes.ts` — Dynamic Project Catalog
- **`GET /api/services`**: Retrieves all monitored applications and microservices with computed active incident counts.
- **`POST /api/services`**: Allows SuperAdmin to register a new service asset (e.g., adding a new mobile app or microservice).
- **`PATCH /api/services/:id`**: Allows SuperAdmin to rename, update SLA thresholds, or change environments.
- **`DELETE /api/services/:id`**: Allows SuperAdmin to decommission services from the catalog.

#### 4. `apps/api/src/routes/ai.routes.ts` — AI Copilot Endpoints
- **`POST /api/ai/triage`**: Takes raw error title, description, and affected URL; returns structured AI diagnosis (`aiRootCause`, `aiSuggestedAction`, `aiConfidence`, `slaTargetMins`).
- **`GET /api/ai/shift-briefing`**: Synthesizes all active tickets across the entire enterprise into a cohesive shift summary for engineering management.

#### 5. `apps/api/src/routes/task.routes.ts` & `stats.routes.ts`
- Manages sub-tasks and computes real-time SLA compliance percentages (e.g., 88% compliance).

---

### 🧠 Backend AI Services (`apps/api/src/services/`)

#### `apps/api/src/services/ai.service.ts`
- **Google Gemini 1.5 Flash Integration**: Uses frontier LLM capabilities via `@google/genai` to analyze cryptic stack traces and error codes.
- **Autonomous Fallback Engine**: If running in disconnected or offline environments without an API key, an intelligent heuristic engine pattern-matches against 30+ enterprise scenarios:
  - *504 Gateway Timeout* ➔ Inactive upstream service, proxy timeout, pod failure.
  - *Connection Pool Exhaustion* ➔ PostgreSQL deadlock, connection leak.
  - *OOMKilled* ➔ Kubernetes container memory limit exceeded.
  - *SSL Handshake Failure* ➔ Expired certificate or cipher mismatch.
- Returns clean JSON contracts with root cause, remediation steps, priority, and SLA target.

## 💻 PART 3: The Web Portal (`apps/web/src/app`)

Built with **Next.js 15, React 19, and Vanilla CSS** on port `3000`.

### 📄 `apps/web/src/app/layout.tsx` — Root HTML Shell
- Preconnects to Google Fonts (`Plus Jakarta Sans` and `JetBrains Mono`).
- **Inlined Critical Styling**: Synchronously injects the entire design system stylesheet into the `<head>` of the initial HTML document via `<style id="workmate-critical-theme">`.
- This ensures that under no circumstances (dev cache rebuilds, network latency, or strict browser ad-blockers) will the application render as unstyled plain HTML.

### 📄 `apps/web/src/app/globals.css` — The Design System
- Curated design tokens:
  - Deep dark background: `#090d16`.
  - Glassmorphic card surfaces: `rgba(15, 23, 42, 0.65)`.
  - Accent colors: Indigo (`#6366f1`), Cyan (`#06b6d4`), Emerald (`#10b981`), Rose (`#f43f5e`), Purple (`#a855f7`).
- Implements responsive grid layouts, Jira Kanban column styling, modal dialog backdrops, and interactive micro-animations.

---

### 📄 `apps/web/src/app/page.tsx` — The Interactive Dashboard
This file contains the complete single-page application with 6 dedicated tabs:

#### 1. Header Bar & Navigation
- Branding badge (`⚡ WorkMate AI · Jira & ServiceNow Operations`).
- Live database indicator (`Neon Postgres Connected`).
- Action buttons: **`+ Log Ticket`**, **`+ Add User`** (SuperAdmin only), and User Profile / Sign In pill with **`Log Out`**.

#### 2. Tab 1: Command Dashboard (`activeTab === "command"`)
- **Metric Cards**: Active Incidents, Urgent Alerts, SLA Compliance Percentage (`88%`), and Task Completion Velocity.
- **Executive Shift Briefing**: Live AI-generated summary of platform health and incident trends.
- **Department Workload Grid**: Visual distribution of open tickets across Backend, Frontend, DevOps, and QA squads.

#### 3. Tab 2: Jira Ticketing Tool (`activeTab === "tickets"`)
- **Kanban Board**: 5 interactive columns:
  - `OPEN` (New unassigned incidents).
  - `ASSIGNED` (Allocated to an engineer).
  - `IN_PROGRESS` (Active remediation under way).
  - `RESOLVED` (Fix verified; SLA timer stopped).
  - `CLOSED` (Incident finalized and archived).
- **Table View**: Compact data grid with real-time text search, status filters, and category badges.
- **Role Scoping Filter**: Lets users switch view perspectives:
  - *My Role Incidents*
  - *Assigned to Me*
  - *Reported by Me*
  - *All Organization Tickets*

#### 4. Tab 3: Applications & Websites (`activeTab === "services"`)
- Interactive cards representing monitored services (APIs, Web Apps, Databases, Cloud Clusters).
- Displays active incident count, environment badge, and SLA target time.
- **SuperAdmin Authority**: SuperAdmins can add new services (`+ Add Project`), edit/rename existing services, or delete decommissioned projects.

#### 5. Tab 4: Team & Roles (`activeTab === "users"`)
- Directory of all registered employees with role tags (`SUPER_ADMIN`, `ENGINEER`, `MANAGER`, etc.).
- SuperAdmin can create new accounts and assign default or custom passwords.

#### 6. Tab 5: Work Orders (`activeTab === "tasks"`)
- Action checklist view for engineers to track granular remediation tasks.

#### 7. Tab 6: AI Triage Hub (`activeTab === "sandbox"`)
- Interactive testing laboratory to paste raw error logs, select affected microservices, and observe Google Gemini's autonomous triage in real time.

#### 8. Modals
- **Incident Detail Modal**: Displays full incident details, AI root cause card, SLA countdown, lifecycle status buttons, and live comments thread.
- **Authentication Modal**: Supports real-time Email + Password sign-in, show/hide password toggle (`👁️` / `🙈`), quick 1-click test logins, and user registration.
- **Log Ticket Modal**: Service selector, title, description, and AI triage toggle.

## 🔄 PART 5: End-to-End Incident Lifecycle Walkthrough

To see how all pages and code files work together, follow this end-to-end incident flow:

```
[1. User / Monitoring Alert]
         │
         ▼
[2. apps/web/src/app/page.tsx: New Ticket Modal]
         │  Payload: { title, description, serviceAssetId, runAiTriage: true }
         ▼
[3. apps/api/src/routes/issue.routes.ts]
         │  Validates input using Zod
         ▼
[4. apps/api/src/services/ai.service.ts]
         │  Calls Google Gemini 1.5 Flash
         │  Returns: Root Cause, Remediation Steps, Urgency, SLA Target
         ▼
[5. Neon Cloud PostgreSQL]
         │  Prisma saves record to table "Issue"
         ▼
[6. Web Kanban Board Updates]
         │  Card appears in "OPEN" column with 15-min countdown timer
         ▼
[7. On-Call Mobile App (apps/mobile) Alerts Engineer]
         │  Engineer opens ticket on phone
         │  Reads AI remediation recommendations
         │  Taps "In Progress"
         ▼
[8. Engineer Executes Fix & Resolves Ticket]
         │  Posts update comment: "Scaled Redis workers to 12. Latency resolved."
         │  Taps "Resolve"
         │  SLA timer stops; database records resolution timestamp
         ▼
[9. Command Dashboard Metrics Update]
         │  SLA compliance percentage recalculated
         │  AI Shift Briefing incorporates the resolved incident!
```
